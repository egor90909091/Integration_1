Шаблон - Composed Message Processor

Инициатор отправляет заявку с несколькими видами работ. Разделитель режет ее на части, маршрутизатор отправляет каждую часть своему сервису (бурение, электрика, логистика), сервисы считают цену и срок, агрегатор собирает все расчеты в одну смету и отправляет обратно инициатору.

Паттерны:
- Splitter - делим заявку на части
- Content-Based Router - выбираем сервис по типу работы
- Aggregator - собираем расчеты в смету
- Correlation Identifier - по correlation_id понимаем какие расчеты от какой заявки
- Return Address - в reply_to инициатор указывает куда прислать смету
- Request-Reply - отправили заявку, получили смету
- Guaranteed Delivery - если сервис выключен, части ждут в очереди и досчитаются когда он вернется
